운영을 멈추지 않고 플랫폼을 다시 만듭니다

오래된 플랫폼에는 아무도 쓰지 않는 기능과 아무도 건드리고 싶지 않은 데이터가 쌓입니다. 재구축에 남길 것, 뺄 것, 데이터를 옮기는 방법을 함께 정하고, 운영이 계속 돌아가도록 단계별로 출시합니다.

재구축에 포함되는 것

  • 현재 기능, 사용자, 의존 관계 검토
  • 첫 출시 범위와 이후 개선 범위 구분
  • 검증을 포함한 단계별 데이터 이관 계획
  • 출시 전에 정하는 부하·검수 기준
  • 운영 인계와 출시 점검

재구축이 일정을 넘기는 이유

기존 기능을 전부 새 버전에 옮기려 하고, 데이터 이관은 마지막으로 미루기 때문입니다. 실제 사용 현황부터 보고 더 작은 첫 출시를 합의하며, 데이터 이관은 처음부터 단계별로, 부분마다 책임자를 정해 계획합니다.

  2. 02약 100개국 대상 글로벌 학습 플랫폼 전환: 3단계 데이터 이관 전략, 사용자 2만 명 규모 부하 테스트 기준 정의

디시저너리 소개

디시저너리(Decisionary)는 서울에 있는 외주 개발사입니다. 기업과 디지털 에이전시의 웹 애플리케이션, 기존 서비스 재구축, API·시스템 연동을 맡습니다. 개발 전에 범위와 검수 기준을 문서로 합의하고, 대표가 납품까지 직접 이끕니다.

자주 묻는 질문

한 번에 전부 옮겨야 하나요?

아닙니다. 재구축과 데이터 이관을 단계별로 계획해, 각 부분이 준비될 때까지 기존 플랫폼은 계속 운영됩니다.

사내 개발팀과 함께 일할 수 있나요?

네. 고객사 팀, 전문 인력, 디시저너리의 역할을 프로젝트 시작 전에 나눠 정합니다.
