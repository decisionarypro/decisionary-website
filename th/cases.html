01 · การศึกษา · 2025–2026

โปรเจกต์ที่ผู้ก่อตั้งเป็นผู้นำในตำแหน่งก่อนหน้า

ปรับปรุงและย้ายข้อมูลแพลตฟอร์มการเรียนรู้ระดับโลก

บทบาทของผู้ก่อตั้ง: กลยุทธ์ผลิตภัณฑ์และประสานงานโปรแกรม

พร้อมเปิดเบต้าใน ~100 ประเทศ

ภาพรวม

โปรเจกต์ปรับปรุงแพลตฟอร์มการเรียนรู้ข้ามชาติที่ให้บริการผู้ใช้ในประมาณ 100 ประเทศ

แพลตฟอร์มต้องรองรับโครงสร้างองค์กร สิทธิ์ผู้ใช้ การมอบหมายการเรียน ระบบจูงใจ และข้อกำหนดการดำเนินงานของแต่ละภูมิภาค โดยยังคงฟังก์ชันหลักให้สอดคล้องกัน

โปรเจกต์ยังรวมถึงการย้ายข้อมูลผู้ใช้และข้อมูลการเรียนจากแพลตฟอร์มเดิมไปยังระบบใหม่ ซึ่งต้องประสานงานระหว่างฝ่ายธุรกิจ ทีมเทคนิค และฝ่ายปฏิบัติการ

ความท้าทาย

แพลตฟอร์มต้องสร้างสมดุลระหว่างบริการที่สอดคล้องกันทั่วโลกกับกฎเฉพาะของแต่ละองค์กรและข้อกำหนดการดำเนินงานในแต่ละพื้นที่

ทีมพัฒนาหลายทีมทำงานภายใต้กำหนดเปิดตัวที่จำกัด ขณะที่การย้ายข้อมูล การเข้าถึงของผู้ใช้ การตรวจสอบระบบ และความพร้อมในการดำเนินงาน ทำให้เกิดการพึ่งพากันในหลายส่วนของโปรเจกต์

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งรับบทบาทด้านกลยุทธ์ผลิตภัณฑ์และผู้นำโปรเจกต์ ประสานความต้องการและการตัดสินใจสำคัญระหว่างฝ่ายธุรกิจ ผลิตภัณฑ์ ออกแบบ พัฒนา โครงสร้างพื้นฐาน และองค์กรพันธมิตร งานหลักได้แก่

  • วางนโยบายการเข้าถึงและสิทธิ์ระดับองค์กร
  • กำหนดกฎทางธุรกิจเกี่ยวกับการมอบหมายการเรียน ระบบจูงใจ และการจัดอันดับ
  • ประสานนโยบายบริการที่เกี่ยวกับเขตเวลา
  • วางหลักการย้ายข้อมูลเป็นระยะสำหรับผู้ใช้ องค์กร สิทธิ์ และประวัติการเรียน
  • แบ่งความรับผิดชอบระหว่างการย้ายผ่าน API และการย้ายแบบกลุ่ม
  • สนับสนุนแผน QA จุดตรวจก่อนเปิดตัว และการส่งต่องานปฏิบัติการ
  • แยกความต้องการที่จำเป็นสำหรับการเปิดตัวออกจากงานปรับปรุงหลังเปิดตัว

ผลลัพธ์

ตามบันทึกของโปรเจกต์
  1. 01สนับสนุนความพร้อมในการเปิดเบต้าเดือนเมษายน 2026 สำหรับประมาณ 100 ประเทศ
  2. 02วางกลยุทธ์การย้ายข้อมูลสามระยะ
  3. 03กำหนดเกณฑ์การทดสอบโหลดที่ระดับผู้ใช้ 20,000 คน
  4. 04เพิ่มความสอดคล้องเรื่องขอบเขตการเปิดตัว การพึ่งพา และเกณฑ์การตรวจรับ

02 · ประกันภัย · 2018–2019

โปรเจกต์ที่ผู้ก่อตั้งเป็นผู้นำในตำแหน่งก่อนหน้า

แพลตฟอร์มจำหน่ายประกันภัย B2B2C

บทบาทของผู้ก่อตั้ง: บริหารผลิตภัณฑ์และประสานการเชื่อมต่อ

อัตราการสมัครสำเร็จ 12% → 28%

ภาพรวม

แพลตฟอร์มจำหน่ายประกันภัยดิจิทัลที่เชื่อมบริษัทประกัน พันธมิตรผู้จำหน่าย และลูกค้าปลายทาง

แพลตฟอร์มรองรับการสมัครประกันผ่านช่องทางพันธมิตร ครอบคลุมขั้นตอนฝั่งลูกค้า ฟังก์ชันผู้ดูแลระบบ งานที่เกี่ยวกับการชำระเงิน และการเชื่อมต่อระบบภายนอก

เป้าหมายคือทำให้การสมัครประกันง่ายขึ้น พร้อมรองรับข้อกำหนดการดำเนินงานของหลายองค์กรที่เกี่ยวข้อง

ความท้าทาย

การสมัครประกันต้องให้ลูกค้ากรอกข้อมูลจำนวนมาก พันธมิตรแต่ละรายมีข้อกำหนดต่างกัน และมีหลายขั้นตอนการดำเนินงานเกี่ยวข้อง

การออกแบบหน้าจอลูกค้าใหม่เพียงอย่างเดียวไม่พอ กฎของผลิตภัณฑ์ การเชื่อมต่อพันธมิตร ฟังก์ชันผู้ดูแล และขั้นตอนการชำระเงินและกระทบยอดต้องทำงานร่วมกันอย่างสอดคล้อง

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งดูแลโครงสร้างผลิตภัณฑ์ของแพลตฟอร์ม ขั้นตอนการสมัครของลูกค้า ความต้องการของผู้ดูแล และการประสานการเชื่อมต่อกับพันธมิตร งานหลักได้แก่

  • ออกแบบขั้นตอนการสมัครของลูกค้าใหม่
  • กำหนดความต้องการของผลิตภัณฑ์ประกันและฟังก์ชันการจัดการ
  • วางโครงสร้างฟังก์ชันฝั่งลูกค้าและฝั่งผู้ดูแล
  • ประสานความต้องการระหว่างบริษัทประกันและพันธมิตรผู้จำหน่าย
  • ทำให้การเชื่อมต่อ API ของพันธมิตรสอดคล้องกับขั้นตอนของผลิตภัณฑ์
  • จัดการกรณีพิเศษด้านการดำเนินงานในการสมัคร การชำระเงิน และการกระทบยอด

ผลลัพธ์

ตามบันทึกของโปรเจกต์
  1. 01อัตราการสมัครสำเร็จเพิ่มจาก 12% เป็น 28%
  2. 02เวลาสมัครเฉลี่ยลดจาก 8 นาทีเหลือ 3 นาที
  3. 03ช่องทาง API ของพันธมิตรสร้างลูกค้าใหม่ประมาณ 1,200 ราย
  4. 04วางโครงสร้างผลิตภัณฑ์และการดำเนินงานที่สอดคล้องกันมากขึ้นระหว่างทุกฝ่าย

03 · การเดินทาง · 2022

โปรเจกต์ที่ผู้ก่อตั้งเป็นผู้นำในตำแหน่งก่อนหน้า

สร้างแอปการเดินทางใหม่

บทบาทของผู้ก่อตั้ง: หัวหน้าผลิตภัณฑ์และการส่งมอบ

เปิดตัวใน 66 วัน

ภาพรวม

โปรเจกต์สร้างแอปการเดินทางสำหรับผู้บริโภคใหม่ เน้นปรับปรุงประสบการณ์ผู้ใช้ ทำให้ผลิตภัณฑ์เรียบง่าย และเปิดตัวแอปในเวลาจำกัด

แทนที่จะคงฟีเจอร์เดิมไว้ทั้งหมด โปรเจกต์ต้องทบทวนความต้องการของผู้ใช้และเลือกชุดฟีเจอร์ที่มีคุณค่าสูงจำนวนหนึ่งสำหรับการเปิดตัวครั้งแรก

ความท้าทาย

แอปเดิมสะสมฟีเจอร์ไว้มาก ทำให้ซับซ้อนทั้งสำหรับผู้ใช้และทีมพัฒนา

โปรเจกต์ต้องสร้างสมดุลระหว่างการปรับปรุงการใช้งาน คุณภาพทางเทคนิค กำลังการพัฒนา และกำหนดเปิดตัว โดยไม่ขยายขอบเขตครั้งแรกโดยไม่จำเป็น

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งเป็นผู้นำการกำหนดขอบเขตผลิตภัณฑ์และการประสานงานพัฒนาข้ามสายงาน งานหลักได้แก่

  • สัมภาษณ์ผู้ใช้และทดสอบการใช้งาน 23 ครั้ง
  • ประเมินฟีเจอร์ที่เสนอ 36 รายการตามความต้องการของลูกค้าและลำดับความสำคัญในการพัฒนา
  • กำหนดฟีเจอร์ MVP 15 รายการ
  • ประสานทีม 11 คนด้านผลิตภัณฑ์ ออกแบบ และพัฒนา
  • บริหารลำดับความสำคัญของสปรินต์ การพึ่งพาในการพัฒนา และหมุดหมายการเปิดตัว
  • สนับสนุนการปรับปรุงคุณภาพและแก้ไขปัญหาก่อนเปิดตัว

ผลลัพธ์

ตามบันทึกของโปรเจกต์
  1. 01ลดฟีเจอร์ที่เสนอ 36 รายการเหลือ MVP ที่จัดลำดับความสำคัญ 15 รายการ
  2. 02เปิดตัวแอปที่ปรับปรุงแล้วใน 66 วัน
  3. 03เปิดตัวเร็วกว่าแผนเดิมประมาณ 27%
  4. 04บันทึกของโปรเจกต์ระบุว่าผู้ใช้งานรายเดือนเพิ่มขึ้น 32%
  5. 05อัตราแอปขัดข้องลดจาก 4.2% เหลือ 0.8%

04 · บริการแปลภาษา · 2023

โปรเจกต์ที่ผู้ก่อตั้งเป็นผู้นำในตำแหน่งก่อนหน้า

SaaS บริหารงานแปลและการแปลงงานเป็นดิจิทัล

บทบาทของผู้ก่อตั้ง: ผู้จัดการผลิตภัณฑ์

ลดเวลาบริหาร ~40%

ภาพรวม

ระบบบริหารงานแปลที่ช่วยเพิ่มประสิทธิภาพการประสานงานโปรเจกต์และการดำเนินงานของบริการแปลมืออาชีพ

เดิมทีกระบวนการแปลทั้งหมดอาศัยการประสานงานด้วยมือซ้ำๆ การตรวจสอบสถานะ และการติดต่อระหว่างผู้เกี่ยวข้อง

โปรเจกต์มุ่งเปลี่ยนความต้องการด้านการดำเนินงานเหล่านี้ให้เป็นผลิตภัณฑ์ซอฟต์แวร์ที่มีโครงสร้าง

ความท้าทาย

ต้องลดภาระงานบริหาร พร้อมทั้งทำให้เห็นความคืบหน้าของโปรเจกต์แปลและความรับผิดชอบในการส่งมอบได้ชัดเจนขึ้น

การเข้าใจวิธีทำงานจริงเป็นสิ่งสำคัญก่อนเลือกฟีเจอร์และกำหนดขอบเขตการเปิดตัวครั้งแรก

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งวิเคราะห์ขั้นตอนการทำงานของนักแปลผ่านการสัมภาษณ์ผู้ใช้และการทบทวนกระบวนการดำเนินงาน งานหลักได้แก่

  • จัดทำแผนผังขั้นตอนการทำงานเดิมและระบุคอขวด
  • กำหนดความต้องการของผู้ใช้และความต้องการของระบบตามบทบาท
  • วางโครงสร้างฟังก์ชัน MVP และลำดับความสำคัญในการพัฒนา
  • ปรับความต้องการให้สอดคล้องกับคุณค่าทางธุรกิจและความยากในการพัฒนา
  • บริหารกำหนดการ ปัญหา และความเสี่ยงในการส่งมอบของโปรเจกต์

ผลลัพธ์

ตามบันทึกของโปรเจกต์
  1. 01เวลาบริหารโปรเจกต์แปลลดลงประมาณ 40% หลังใช้ระบบ
  2. 02อัตราการทำตามกำหนดเวลาโปรเจกต์ถึง 95%

ภาพรวม

โปรเจกต์ปรับปรุงผลิตภัณฑ์ของแพลตฟอร์มมือถือสำหรับผู้บริโภคที่เปิดให้บริการอยู่แล้ว

เป้าหมายคือค้นหาจุดที่ผู้ใช้ติดขัดในเส้นทางการใช้งานเดิม จัดลำดับการปรับปรุง และเพิ่มการมีส่วนร่วม การรักษาผู้ใช้ และคุณภาพบริการ

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งทำงานร่วมกับทีมวิเคราะห์ข้อมูล ความคิดเห็นของผู้ใช้ และทีมพัฒนาผลิตภัณฑ์ เพื่อหาโอกาสในการปรับปรุงและวางกระบวนการเปิดตัวที่เป็นระบบ งานหลักได้แก่

  • วิเคราะห์ช่องทางการสมัครและการใช้ฟีเจอร์ด้วย Google Analytics และ Firebase
  • ระบุจุดที่ผู้ใช้หลุดออก 3 จุดที่ต้องปรับปรุงก่อน
  • กำหนดลำดับความสำคัญของการปรับปรุง UI/UX และการทดลอง
  • ประสานการทดสอบ A/B และการตัดสินใจเรื่องแบ็กล็อกของผลิตภัณฑ์
  • ดำเนินรอบการเปิดตัวเป็นประจำทุกประมาณสองถึงสามสัปดาห์

06 · ภาครัฐและการท่องเที่ยว · 2023–2024

โปรเจกต์ที่ผู้ก่อตั้งเป็นผู้นำในตำแหน่งก่อนหน้า

แพลตฟอร์มคีออสก์ดิจิทัลเพื่อการท่องเที่ยวภาครัฐ

บทบาทของผู้ก่อตั้ง: ผู้นำด้านผลิตภัณฑ์และโปรเจกต์

อันดับ 1 การประเมินทางเทคนิค

ภาพรวม

โปรเจกต์คีออสก์ดิจิทัลที่ให้นักท่องเที่ยวแตะหน้าจอเพื่อค้นหาข้อมูลท่องเที่ยวได้เอง

โซลูชันต้องสอดคล้องกันทั้งข้อกำหนดบริการภาครัฐ การใช้งานของนักท่องเที่ยว ฟังก์ชันซอฟต์แวร์ และขีดความสามารถของผู้จัดหาฮาร์ดแวร์

ความท้าทาย

คีออสก์ในพื้นที่สาธารณะต้องใช้งานได้กับนักท่องเที่ยวหลายกลุ่ม พร้อมทั้งเป็นไปตามข้อกำหนดการจัดซื้อและข้อจำกัดในการติดตั้งจริง

ความสำเร็จขึ้นอยู่กับการกำหนดเส้นทางของนักท่องเที่ยวให้ชัดเจน และการประสานงานระหว่างผู้เกี่ยวข้องกับบริการและผู้จัดหาภายนอก

บทบาทของผู้ก่อตั้ง

ผู้ก่อตั้งรับผิดชอบกลยุทธ์ผลิตภัณฑ์ ความต้องการด้านประสบการณ์ผู้ใช้ การประสานงานผู้จัดหา และงานเสนอโปรเจกต์ งานหลักได้แก่

  • สัมภาษณ์และสังเกตภาคสนามกับกลุ่มผู้ใช้ห้ากลุ่ม
  • กำหนดสถานการณ์ของนักท่องเที่ยวและความต้องการในการค้นหาข้อมูล
  • วางโครงสร้างฟังก์ชันและข้อกำหนดหน้าจอสำหรับผู้ใช้
  • ประสานความต้องการของผลิตภัณฑ์กับผู้จัดหาฮาร์ดแวร์
  • เป็นผู้นำการจัดทำข้อเสนอและการนำเสนอสำหรับโปรเจกต์ภาครัฐ

  2. 02ประสานความต้องการด้านฟังก์ชันและการดำเนินงานกับผู้จัดหาภายนอก
