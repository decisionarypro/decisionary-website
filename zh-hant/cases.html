01 · 教育 · 2025–2026

創辦人在過去任職或合約中主導的專案

全球學習平台升級與資料移轉

創辦人角色: 產品策略與專案統籌

約 100 國公開測試準備

概述

面向約 100 個國家使用者的跨國學習平台升級專案。

平台需要在維持核心功能一致的同時，支援不同的組織架構、使用者權限、學習指派、獎勵機制與各地區的營運要求。

專案也包含將舊平台的使用者與學習資料移轉至新環境，需要業務單位、技術團隊與營運部門之間的協調。

挑戰

平台需要在全球一致的服務與各組織的規則、各地營運要求之間取得平衡。

多個開發團隊在緊湊的上線時程下工作，而資料移轉、使用者存取、系統驗證與營運準備，在專案各部分之間形成了相依關係。

創辦人的貢獻

創辦人擔任產品策略與專案負責人的角色，在業務、產品規劃、設計、開發、基礎設施與合作夥伴組織之間協調需求與關鍵決策。主要工作包括：

  • 設計組織層級的存取與權限政策
  • 定義學習指派、獎勵與排名相關的業務規則
  • 協調與時區相關的服務政策
  • 制定使用者、組織、權限與學習紀錄的分階段資料移轉原則
  • 釐清以 API 移轉與批次移轉的責任範圍
  • 支援 QA 計畫、上線檢查與營運交接
  • 區分上線必要需求與上線後的改善項目

成果

以專案紀錄為準
  1. 01支援面向約 100 個國家、2026 年 4 月公開測試的上線準備
  2. 02制定三階段資料移轉策略
  3. 03定義 2 萬名使用者規模壓力測試的驗證標準
  4. 04提升各方對上線範圍、相依關係與驗收標準的共識

02 · 保險 · 2018–2019

創辦人在過去任職或合約中主導的專案

B2B2C 保險銷售平台

創辦人角色: 產品管理與串接統籌

投保轉換率 12% → 28%

概述

連結保險公司、銷售夥伴與最終客戶的數位保險銷售平台。

平台支援透過合作夥伴通路投保，涵蓋面向客戶的流程、管理功能、付款相關作業與外部系統串接。

目標是在滿足多個參與機構營運要求的同時，簡化投保流程。

挑戰

投保需要客戶填寫大量資料，各合作夥伴的要求不同，也牽涉多個營運流程。

只重新設計客戶介面並不足以減少阻力。商品規則、合作夥伴串接、管理功能，以及付款與結算流程需要彼此配合運作。

創辦人的貢獻

創辦人負責平台的產品架構、客戶投保流程、管理需求與合作夥伴串接的協調。主要工作包括：

  • 重新設計客戶投保流程
  • 定義保險商品與管理功能的需求
  • 規劃面向客戶的功能與後台管理功能的架構
  • 協調保險公司與銷售夥伴之間的需求
  • 讓合作夥伴 API 串接與產品流程保持一致
  • 整理投保、付款與結算過程中的營運例外情況

成果

以專案紀錄為準
  1. 01投保轉換率從 12% 提升至 28%
  2. 02平均投保時間從 8 分鐘縮短為 3 分鐘
  3. 03透過合作夥伴 API 通路取得約 1,200 位新客戶
  4. 04在各參與方之間建立更一致的產品與營運架構

03 · 交通出行 · 2022

創辦人在過去任職或合約中主導的專案

交通出行 App 重建

創辦人角色: 產品與上線統籌

66 天上線

概述

以改善使用者體驗、簡化產品，並在有限時間內推出行動 App 為重點的消費者交通出行 App 重建專案。

專案沒有沿用所有既有功能，而是重新檢視使用者需求，為首次發布挑選出價值較高的少量功能。

挑戰

既有 App 累積了大量功能，對使用者與開發團隊都造成了複雜度。

專案需要在不擴大首發範圍的前提下，兼顧易用性改善、技術品質、開發量能與上線時程。

創辦人的貢獻

創辦人主導產品範圍定義與跨職能開發協調。主要工作包括：

  • 進行 23 次使用者訪談與易用性測試
  • 依客戶需求與實作優先順序評估 36 項候選功能
  • 確定 15 項 MVP 功能
  • 協調由產品規劃、設計與開發組成的 11 人團隊
  • 管理衝刺優先順序、開發相依關係與上線里程碑
  • 支援上線前的品質改善與問題排除

成果

以專案紀錄為準
  1. 01將 36 項候選功能精簡為 15 項優先 MVP 功能
  2. 0266 天內推出改版 App
  3. 03比原定計畫提前約 27% 完成上線
  4. 04專案紀錄顯示月活躍使用者成長 32%
  5. 05App 當機率從 4.2% 降至 0.8%

04 · 翻譯服務 · 2023

創辦人在過去任職或合約中主導的專案

翻譯管理 SaaS 與業務數位化

創辦人角色: 產品經理

管理時間減少約 40%

概述

提升專業翻譯服務專案協調與營運效率的翻譯管理系統。

過去，整個翻譯流程仰賴重複的人工協調、進度確認與參與者之間的溝通。

專案著重於把這些營運需求轉化為有架構的軟體產品。

挑戰

需要在減輕管理負擔的同時，讓翻譯專案的進度與交付責任更清楚可見。

在挑選功能、確定首次發布範圍之前，先了解實際的工作方式至關重要。

創辦人的貢獻

創辦人透過使用者訪談與營運流程檢視，分析譯者的工作流程。主要工作包括：

  • 整理既有營運流程並找出瓶頸
  • 定義使用者需求與各角色的系統需求
  • 規劃 MVP 功能與開發優先順序
  • 依商業價值與開發難度調整需求
  • 管理專案時程、問題與交付風險

成果

以專案紀錄為準
  1. 01導入翻譯管理系統後，翻譯專案管理時間減少約 40%
  2. 02專案時程達成率達 95%
  3. 03依實際營運流程確定 MVP 優先範圍

05 · 行動消費服務 · 2023–2024

創辦人在過去任職或合約中主導的專案

行動平台優化

創辦人角色: 產品與業務統籌

月活躍使用者成長 42%

概述

針對已營運之消費者行動平台的產品改善專案。

目標是找出既有使用者旅程中的阻力點、決定改善優先順序，進而提升使用者參與度、留存率與整體服務品質。

創辦人的貢獻

創辦人與數據分析、使用者回饋及產品開發團隊一起找出改善機會，並建立有系統的發布流程。主要工作包括：

  • 透過 Google Analytics 與 Firebase 分析註冊與功能使用漏斗
  • 找出 3 個需優先改善的流失節點
  • 確定 UI/UX 改善與實驗的優先順序
  • 協調 A/B 測試與產品待辦清單的決策
  • 以約 2–3 週為週期定期發布

成果

以專案紀錄為準
  1. 01月活躍使用者成長 42%
  2. 02使用者留存率提升 28 個百分點
  3. 03點擊率提升 18%
  4. 04App 商店評分從 3.2 提升至 4.6

06 · 公共與觀光 · 2023–2024

創辦人在過去任職或合約中主導的專案

公共觀光數位資訊站平台

創辦人角色: 產品與專案統籌

技術評選第一名得標

概述

讓遊客直接操作螢幕查詢觀光資訊的數位資訊站專案。

方案需要兼顧公共服務要求、遊客的易用性、軟體功能與硬體供應商的能力。

挑戰

設置於公共場所的資訊站需要讓不同遊客都能使用，同時符合採購要求與實際設置條件。

成敗取決於能否清楚定義遊客動線，並協調服務相關單位與外部供應商。

創辦人的貢獻

創辦人負責產品策略、使用者體驗需求、供應商協調與專案提案工作。主要工作包括：

  • 針對 5 類使用者族群進行訪談與現場觀察
  • 定義遊客情境與資訊查詢需求
  • 規劃面向使用者的功能與介面需求
  • 與硬體供應商協調產品需求
  • 主導公共專案的提案撰寫與簡報

成果

以專案紀錄為準
  1. 01以 5 類使用者族群為基礎建立使用者體驗需求
  2. 02與外部供應商協調功能與營運需求
  3. 03在相關採購程序中獲得技術評選第一名
  4. 04取得公共專案
