01 · 教育 · 2025–2026

创始人在以往任职或合约中主导的项目

全球学习平台升级与数据迁移

创始人角色: 产品战略与项目统筹

约 100 个国家的公测准备

概述

面向约 100 个国家用户的跨国学习平台升级项目。

平台需要在保持核心功能一致的同时，支持不同的组织结构、用户权限、学习分配、激励机制和各地区的运营要求。

项目还包括将旧平台的用户与学习数据迁移到新环境，需要业务方、技术团队和运营部门之间的协调。

挑战

平台需要在全球一致的服务与各组织的规则、各地运营要求之间取得平衡。

多个开发团队在紧张的上线时间表下工作，而数据迁移、用户访问、系统验证和运营准备在项目各部分之间形成了依赖关系。

创始人的贡献

创始人承担产品战略和项目负责人的角色，在业务、产品规划、设计、开发、基础设施和合作伙伴组织之间协调需求与关键决策。主要工作包括：

  • 设计组织级的访问与权限策略
  • 定义学习分配、激励和排名相关的业务规则
  • 协调与时区相关的服务策略
  • 制定用户、组织、权限和学习记录的分阶段数据迁移原则
  • 理清基于 API 的迁移与批量迁移的责任范围
  • 支持 QA 计划、上线检查和运营交接
  • 区分上线必需的需求与上线后的改进事项

成果

以项目记录为准
  1. 01支持面向约 100 个国家、2026 年 4 月公测的上线准备
  2. 02制定三阶段数据迁移策略
  3. 03定义 2 万用户规模压力测试的验证标准
  4. 04提升各方对上线范围、依赖关系和验收标准的共识

02 · 保险 · 2018–2019

创始人在以往任职或合约中主导的项目

B2B2C 保险销售平台

创始人角色: 产品管理与对接统筹

投保转化率 12% → 28%

概述

连接保险公司、销售伙伴和最终客户的数字保险销售平台。

平台支持通过合作伙伴渠道投保，涵盖面向客户的流程、管理功能、支付相关业务以及外部系统对接。

目标是在满足多个参与机构运营要求的同时，简化投保流程。

挑战

投保需要客户填写大量信息，各合作伙伴的要求不同，还涉及多个运营流程。

仅重新设计客户界面不足以减少阻力。产品规则、合作伙伴对接、管理功能以及支付和结算流程需要协同运作。

创始人的贡献

创始人负责平台的产品结构、客户投保流程、管理需求以及合作伙伴对接的协调。主要工作包括：

  • 重新设计客户投保流程
  • 定义保险产品与管理功能的需求
  • 设计面向客户的功能与后台管理功能的结构
  • 协调保险公司与销售伙伴之间的需求
  • 使合作伙伴 API 对接与产品流程保持一致
  • 梳理投保、支付和结算过程中的运营例外情况

成果

以项目记录为准
  1. 01投保转化率从 12% 提升至 28%
  2. 02平均投保时间从 8 分钟缩短至 3 分钟
  3. 03通过合作伙伴 API 渠道获得约 1,200 名新客户
  4. 04在各参与方之间建立更一致的产品与运营结构

03 · 出行 · 2022

创始人在以往任职或合约中主导的项目

出行应用重构

创始人角色: 产品与上线统筹

66 天上线

概述

以改善用户体验、简化产品并在有限时间内上线移动应用为重点的消费级出行应用重构项目。

项目没有沿用全部现有功能，而是重新审视用户需求，为首次发布挑选出价值较高的少量功能。

挑战

现有应用积累了大量功能，给用户和开发团队都带来了复杂性。

项目需要在不扩大首发范围的前提下，兼顾易用性改进、技术质量、开发能力和上线时间。

创始人的贡献

创始人主导了产品范围定义和跨职能开发协调。主要工作包括：

  • 开展 23 次用户访谈和可用性测试
  • 按客户需求和实现优先级评估 36 个候选功能
  • 确定 15 个 MVP 功能
  • 协调由产品规划、设计和开发组成的 11 人团队
  • 管理迭代优先级、开发依赖和上线里程碑
  • 支持上线前的质量改进与问题解决

成果

以项目记录为准
  1. 01将 36 个候选功能精简为 15 个优先 MVP 功能
  2. 0266 天内上线改进版应用
  3. 03比原计划提前约 27% 完成上线
  4. 04项目记录显示月活跃用户增长 32%
  5. 05应用崩溃率从 4.2% 降至 0.8%

04 · 翻译服务 · 2023

创始人在以往任职或合约中主导的项目

翻译管理 SaaS 与业务数字化

创始人角色: 产品经理

管理时间减少约 40%

概述

旨在提升专业翻译服务项目协调与运营效率的翻译管理系统。

过去，整个翻译流程依赖重复的人工协调、进度确认以及参与者之间的沟通。

项目重点是把这些运营需求转化为结构化的软件产品。

挑战

需要在减轻管理负担的同时，让翻译项目的进度和交付责任更加清晰可见。

在选择功能、确定首次发布范围之前，了解实际的工作方式至关重要。

创始人的贡献

创始人通过用户访谈和运营流程审阅，分析了翻译人员的工作流程。主要工作包括：

  • 梳理现有运营流程并找出瓶颈
  • 定义用户需求和各角色的系统需求
  • 规划 MVP 功能与开发优先级
  • 根据业务价值和开发难度调整需求
  • 管理项目进度、问题和交付风险

成果

以项目记录为准
  1. 01引入翻译管理系统后，翻译项目管理时间减少约 40%
  2. 02项目进度达成率达到 95%
  3. 03基于实际运营流程确定 MVP 优先范围

05 · 移动消费服务 · 2023–2024

创始人在以往任职或合约中主导的项目

移动平台优化

创始人角色: 产品与业务统筹

月活跃用户增长 42%

概述

针对已运营的消费级移动平台的产品改进项目。

目标是找出现有用户旅程中的阻力点，确定改进优先级，从而提升用户参与度、留存率和整体服务质量。

创始人的贡献

创始人与数据分析、用户反馈和产品开发团队一起寻找改进机会，并建立了规范的发布流程。主要工作包括：

  • 通过 Google Analytics 和 Firebase 分析注册与功能使用漏斗
  • 找出 3 个需优先改进的流失节点
  • 确定 UI/UX 改进与实验的优先级
  • 协调 A/B 测试和产品待办事项的决策
  • 以约 2–3 周为周期定期发布

成果

以项目记录为准
  1. 01月活跃用户增长 42%
  2. 02用户留存率提升 28 个百分点
  3. 03点击率提升 18%
  4. 04应用商店评分从 3.2 提升至 4.6

06 · 公共与旅游 · 2023–2024

创始人在以往任职或合约中主导的项目

公共旅游数字信息亭平台

创始人角色: 产品与项目统筹

技术评审第一名中标

概述

游客可直接操作屏幕查找旅游信息的数字信息亭项目。

方案需要兼顾公共服务要求、游客的易用性、软件功能和硬件供应商的能力。

挑战

公共场所的信息亭需要让不同游客都能使用，同时满足采购要求和实际部署条件。

成败取决于能否清晰定义游客动线，并协调服务相关方与外部供应商。

创始人的贡献

创始人负责产品战略、用户体验需求、供应商协调和项目提案工作。主要工作包括：

  • 对 5 类用户群体进行访谈和现场观察
  • 定义游客场景与信息查找需求
  • 规划面向用户的功能和界面需求
  • 与硬件供应商协调产品需求
  • 主导公共项目的提案撰写与汇报

成果

以项目记录为准
  1. 01基于 5 类用户群体确立用户体验需求
  2. 02与外部供应商协调功能与运营需求
  3. 03在相关采购程序中获得技术评审第一名
  4. 04赢得公共项目
